## 实际流程

1. 程序进行全桌俯视及四方向基础扫描，然后机械臂复位。
2. A 用 `submit_scene_requirements` 标识任务接触对象和缺失面；程序在有界补拍中取新视角、融合点云并复位。
3. 程序发布全景、对象多视角点图、尺寸、当前双 RGB 和完整手部几何。
4. 同一个 A 每次规划当前一个子任务，通过 `execute_actions` 提交一段带参数草图。
5. 程序顺序执行动作及路点，逐步记录实际状态；失败停止未执行后缀。草图结束或失败后，A 根据真实结果继续当前子任务或规划下一个。

“草图”包含少量关键位姿及动作顺序，不是连续关节轨迹。点表反投影、参考点到EEF的补偿、四元数、IK和绝对关节控制由程序完成。当前不是只含语义骨架的双Agent草图。

## 接口

观察阶段只有 `submit_scene_requirements`，相机位置由程序选取。执行阶段有7个工具：

| 工具 | 用途 |
|---|---|
| `execute_actions` | 提交一段有序、带参数草图 |
| `list_dir` | 列本轮公开目录 |
| `read_text_file` | 分页读公开文本 |
| `read_image` | 读公开原图或点图，并登记可选点源 |
| `get_state` | 读当前机器人与观测几何状态 |
| `refresh_object` | 整理当前RGB-D片段，由A选择关联对象，重建当前位置点图 |
| `finish` | 用真实图像证据报告结束；官方评测另存 |

草图有6种控制动作：`move`、`rotate_roll`、`rotate_pitch`、`rotate_yaw`、`set_gripper`、`wait`。一段最多12项动作；每个 `move` 包含1至本轮 `--max-route-points` 个完整位姿路点，默认最多6个。路点中不放夹爪事件，开闭用独立 `set_gripper`。`set_gripper.target_id` 可显式为 `null`，表示只调夹爪配置而无新对象目标；它不会使无关静物点图失效，但实际原持物参考仍退役，不认证空爪。抓取需要短抬验证时可在同一草图内完成，段末再复核真实结果。

一次回复只提交一条 `execute_actions`、`refresh_object` 或 `finish`，不与其他调用混用；一段草图的多个动作放进同一个 `actions` 数组。重复提交和格式错误均不执行，纠正反馈同时说明调用数量与可验证的语法问题；不自动选取重复调用、不补括号或改动作。默认最多连续4条无效回复，允许3次纠正，可由 `--max-invalid-replies` 配置；格式纠正不占草图段和物理步额度，API/工具尝试仍照实计数。真实运动失败通过执行回执交回A，与格式拒绝分开记录。第三方网关的Schema提示不等于服务端强制JSON生成。

`move` 统一平移、位姿和多路点操作，不向A公开独立的 `move_to`、`move_relative` 或 `move_waypoints`。每点可选择已看点图像素、已看原生图像素或进入该路点时的实际EEF，加米制偏移，并指定或保持完整朝向。程序将选定参考换算为EEF，不要求A查询XYZ或手算四元数。三个 `rotate` 保留为绕世界X/Y/Z原地旋转的便利动作；`move` 保持夹爪命令。

没有B的路线填写、局部修复、冻结B回复重放或 `review_after_route`。A通过自己提交的动作范围决定草图在哪里结束；失败则由程序提前停止。当前T2指交回同一A重新规划；A可在新草图中合并修复动作与仍需执行的剩余动作。程序不自动拼接或恢复旧后缀，已完成动作不重放。

## 数据和上下文

本轮 `agent_public/` 注册文件可读，禁止任意run、密钥、评测GT和路径/链接越界。`scene.json`、`dimensions.json`、`current.json`及目录索引提供资料入口；`geometry/`保留对象RGB/height点图、原始NPZ和精确像素点表，`scene/`保留桌面总图，`observations/`保留历史原生图，`hand/`和`receipts/`保留手部图与实际回执。无需模型手工维护尺寸文件。

当前点图统一从 `current_clouds/latest/` 读取，`index.json`列固定入口及来源步。每个新物理段末，程序冻结已有双RGB-D和公开几何，后台保存原生点表及绘制总图；A可先处理当前双RGB和状态，不等待绘图。`read_image`确实请求尚未完成的新版本时才等待，记录等待秒数；`list_dir`不等待、不渲染、不登记已看。发布只在仿真所属线程进行，旧作业不能把latest倒退。没有额外拍摄、分割或模型调用，不增加默认反馈图片数。

操作提示把读图和物体关联介绍为可选能力，由A根据已有证据决定是否使用，不规定每段查图/刷新。按用户最新要求，柜子/抽屉操作在finish前需读取对应活动部位的latest局部点图，结合当前双RGB检查目标部位闭合及放置结果；历史/预测背景和物体被遮挡不独立证明完成。这只是结束时的说明要求，不新增程序审批、扫描或每段读取。`CURRENT.current_clouds.updated_object_views`给固定图片路径、读取策略和最近展示步；已经发出的旧图片不会自行改变。普通有效夹持搬运按EEF更新本次抓持保留点集的坐标，无需重读；当前原生像素、局部图或`_measured`图可直接提供实测点，不强制先inspect/bind。`refresh_object`提供当前片段整理、显式关联及可选的同次抓持相对位姿重绑，普通bind不恢复旧完整模板。带G编号的点图须填写实际group_id，G0不可选。

对象的 `shape_motion` 描述所引用点集是否会发生内部相对运动，由A在初始观察中声明：`rigid`保留初始形状图与像素→原点ID映射；正常同次有效抓持只按当前EEF变换坐标，不重画局部图。独立移动或滑落后，读取latest形状入口才用当前双RGB-D做一次有界刚体配准，完整且唯一的受支持匹配才开放原模板成员的新坐标，失败则保留历史形状并明确坐标不可用。`articulated`或`unknown`的范围变化后，仅在读取局部 `object_NN_face/side/top.png` 时生成所读角度，同快照重复读复用；刚体也可按需读 `_measured.png` 查看当前实测局部。没有按杯子/微波炉名称硬编码分类，整机与单独门板可有不同范围。

`latest`只更新受控指针，不覆盖旧PNG、点表或 `view_id`。同一 `logical_image_slot` 的新图替代工作请求中的旧图，完整源历史仍可读回。原形状图的轴和高度颜色属于采样时刻。初始完整桌面和对象点集全部保留，显示单独抽样；受支持的刚体只变换精确原成员，不变换邻物。位置未解决的旧表面浅灰显示，不自动给活动结构整体套刚体变换。总图仅作场景上下文；局部只有当前RGB-D实测像素可选，历史背景不可选，选点仍需明确 `reference_target_id`。当前局部1像素、总图3像素，初始图保留9像素。

活动/未知结构的旧点按小空间单元估计运动：RGB-D特征及固定相机的双向光流提出独立刚体运动，只在局部一致、空间支持和当前深度均足够时变换对应原点。仅平面、颜色或深度相似不能确定原表面的身份；已删除试验过的平面推算分支。无特征、特征矛盾、遮挡、竞争位置和预算不足均保留未知。每个原点/颜色/来源不改，重复桌面层仅按同一原观测/相机/像素复用坐标，邻物不随动。此结果只用于背景，仍不能选这些预测点、据此认证完整抽屉、隐藏关节、附着或无碰撞。计算在已有后台作业中进行，不新增图片或模型请求，等待及局部计算时间留档。

实验计费保存 `usage_start.json`、每次真实尝试的 `usage_attempts.jsonl` 和最终 `usage.json`，包含失败/断流重发、请求哈希/图片数、前后余额及查询耗时。余额GET不调用模型。整体余额差与逐次窗口不能重复相加，缺失余额记未知；平台未返回逐请求账单，不能把共享账户余额差冒称独立费用，也不能用套餐名义初始额度推算历史消耗。协议66五次Task3及后续单轮Task0均保留原档；用户最新重新授权后的协议72单轮Task0已结束，未启动后续整套队列，HarnessVLA保持停止。

刚体新抓持保留精确原模板成员与原始坐标，独立位姿和当前接触深度必须支持该模板；当前取景范围不能整体种为持物模板。相对手滑转仍由显式 `rebind_held_pose` 恢复同次抓持原点集，实际夹爪事件建立新抓持。独立配准、刚性传播均不认证夹持、不清除接触警告。初始静物身份纠正同时重指局部入口并撤销错误模板，历史文件保留。

当前观测是原生1024×1024前视与腕部RGB-D。初始、扫描停止、动作结束及失败保存关键帧；每个物理步另录20fps前视视频，API等待不重复静止画面，主线无周期双RGB-D保存。JPEG95仅用于用户授权的API传输，不缩放；原PNG、RGB-D、标定和精确点表保持，真实发送图片及请求大小归档。

主线同一物理步、完整公开机器人状态、相机列表和分辨率都未改变时，重复observe复用原观测ID、原RGB-D及标定，并记录observation_reused，不重复渲染或写文件。新物理步必定重新拍摄，即使机械臂关节没变；同一步状态或图像配置变化也重新拍摄。同一原始观测的全场景点云和展示图可复用；持物声明、接触复核、尺寸和手部图仍按当前语义与接触状态更新。历史数据不删，会话归档中的已存PNG不再重写。

每轮timing.json分别记录相机渲染、RGB-D保存、展示标注、点云/尺寸、手部图、对象资料生成、控制/IK、API、上下文和归档时间。嵌套inclusive时间不能相加，exclusive时间扣除子项后可相加；未覆盖部分明确单列，不统称为点云耗时。API中人工等待时长另见结果字段。

工作上下文默认在超过120000文本字符或80消息时整理，保留最近约40条、60000字符内的完整工具对话、最新状态和所需图像；原始会话与推理完整归档，无额外模型总结。图片窗口默认24张、8MB，初始对象参考、当前实图和最近选读图受保护，旧图通过公开文件读回。这是本轮上下文，不是长期任务经验。

手图仍是一张1024×1024图：三个正投影对照实际蓝手与记录失败目标的橙虚线；第四格显示实际完整活动机械臂、附近实测场景及已记录关节目标的橙虚线。没有记录目标关节分支时不另解IK补图。CURRENT给目标/实际关节、末段移动范围、同一命令持续步数及本轮最近12次失败的原始参数与真实结果索引，完整记录可读。手形采用当前实测开度，目标不是当前姿态或真实碰撞认证，不增加默认图片或模型轮次。

IK-only执行按当前路点的真实入口编译一次关节轨迹并保存制品哈希，实际执行同一轨迹；物理步、机器人状态、夹爪或制品变化则零动作拒绝。下一相对EEF路点仍到其实际入口才绑定。逐步记录当前setpoint跟踪和末段变化，未启用未经校准的正常运动早停。纯跟踪失败不强制重定位整物；本段参考失效、接触警告或A实际观察到变化时保留当前候选/重定位，A也可按需refresh_object。

尺寸、主轴和局部片段都是可见点测量，不能当完整形状或容器净空。物体改变位置后旧世界点失效；静止目的地旧点仍可用。持物点云刚性传播和RGB-D重定位是几何假设，不独立证明附着或抓持。实际夹爪事件与接触变化按相关对象撤销旧参考。

点云由原生RGB-D按相机内参反投影，再用同一步相机外参转换到世界坐标；扫描融合保留原点、颜色及观测/像素来源，显示抽样不删除精确点表。尺寸是选定可见点的范围：遮挡和分组排除桌面附近6毫米区域等因素会漏掉底面，不能把最低可见点当作已知接触底部。说明仅建议按观测质量留出接近、搬运和放置余量，未放宽5毫米动作到位标准，未新增固定高度或任务坐标配方，也未用桌面假设填补隐藏点。

## 执行与恢复

底层真实IK求解并下发绝对关节位置；每个物理步后刷新运动学，再记录同一时刻的状态、相机标定和图像，保留严格FK检查。单位米/弧度，世界坐标，四元数xyzw。当前到位容差5毫米、3度、最大关节误差0.02弧度，补拍位置12毫米。

当前整任务固定IK-only：保留端点/路径IK和关节限位，不启用观测表面碰撞拒绝、自动绕行或无碰撞认证。`ObservedClearance`仍用于持物表面关联和几何参考，不能将其整体删除。

`receipts/index.json`索引本轮全部历史草图、实际回执与拒绝记录。`sketch_NNN.json`保留原始提交、动作/路点映射、派发时真实状态与参数、每步结果；当前回执给出已完成前缀、失败或未知步骤和未派发后缀。未派发的相对EEF点保持原表达式，不提前换算；历史不是当前证据或自动重放命令。格式/绑定拒绝与已接受草图分开，零动作拒绝仍可能保留已经生效的物体变化声明。

T1只换数值初值重求同一位姿，或在误差仍持续减小时继续同一绝对目标最多40物理步；有既有接触基线时逐步检查实测夹爪间隙与接触边界，停滞、接触变化或T1失败交回同一个A。此检查不额外拍图、不认证掉落或真实附着。当前双RGB-D可用于片段重绑及旧形状重定位；未知结果不自动重放已完成动作或旧后缀。原始请求边界支持明确命令继续；当前批次的网络自动重发授权见下文。扫描仅将明确的观测不足/IK不可达作为预期失败；文件、类型及运行时程序异常直接向上传播，停止后续复位与操作，不冒充取景不足。

有明确目标的实际`set_gripper(close)`结束后，另用闭爪前后已保存的原生双RGB-D、实际指垫和夹爪间隙检查局部接触，不依赖整物持物模板。仅当原来张开、闭后间隙不超过3毫米、前后指垫区均无非机器人表面、闭前至少80%采样区被有效深度明确支持为空且闭爪位姿基本不变时，报告接触矛盾、暂停已有持物参考并停止后缀交同A T2；实际闭爪及epoch变化仍保留。遮挡/无效深度/原来已闭合/薄物体线索不足时保持unknown，当前有表面点只表示局部几何支持，不认证目标身份或抓牢。`target_id=null`配置动作跳过此抓取检查。结果以原来源步写入回执和CURRENT.initial_grasp_contact，下一实际夹爪事件退役旧记录；不新增相机动作或模型调用。

API连接异常或不完整流回复会保留正在运行的仿真和同一A会话，写入 `request_recovery/state.json`，等待继续命令；等待期间不推进物理步、不拍新图。修复原API连接后，在另一个终端执行：

```bash
PYTHONPATH=src <python> -m sketchik.request_recovery /absolute/path/to/run resume
```

这会核对原进程、暂停身份、机器人状态和原会话，再重新请求尚未得到完整回复的那一次；已完成动作不重放。当前批次已获用户明确授权：连接超时、EOF及断流由运行控制程序自动提交继续命令，原进程和原输入校验保持；有短暂递增重连等待，不自动重放机器人动作。认证/额度、格式/参数及实际运动失败不在此范围。未获该授权的独立入口仍等待明确命令；结束等待使用同一命令的 `abort`。全部请求与人工等待时长分别留档。该入口依赖原进程仍存活，不能恢复已经关闭的仿真；已完整返回的截断/过滤拒绝不作为连接恢复自动重发。API配置不在继续命令中修改。

v168基线耗时见 `.runtime/seed0_all_v168_network_recovery.csv` 的 `effective_task_wall_s`；失败网络请求及重连等待完整区间单独记录为 `network_fault_excluded_s`，原 `result.json` / `timing.json` 总耗时保持不改。成功API、格式纠正、感知和真实运动照常计入。每轮 `network_recovery_timing.json` 保存可核对区间，`network_retry_policy.json` 标明授权与旧核心计数字段的适用范围，自动重发另记批次审计。

模型自报成功、动作收敛、官方首次成功和停止后的官方评测分别记录。`--completion-diagnostic`继续到A结束、真实后端终止或预算耗尽，用于检查释放及退手；首次/最终官方结果都不发送给A。

## 运行

GPU运行前检查资源；不结束其他人的进程。API地址、模型和密钥来自私有env文件，不在命令中打印密钥。当前用户配置使用Sol low，每请求65536额度；实际提供方执行情况以日志为准。

```bash
PYTHONPATH=src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  /media/wsqlab/more/kaptainiii/projects/AsyncSketch/.venv-rpent/bin/python \
  -m sketchik.task_trial --task 0 --seed 0 --init-state 0 \
  --max-episode-steps 9000 --max-turns 30 --max-tool-calls 100 \
  --max-subtasks 16 --max-route-points 6 --completion-diagnostic \
  --image-jpeg-quality 95 --reference-exact-images --a-image-window \
  --api-max-tokens 65536 --api-stream --api-budget-field max_completion_tokens \
  --env-file .runtime/flowith_probe/private/gpt.env \
  --gpu-uuid '<GPU UUID>' --output runs/<new-run-name>
```

基础扫描默认执行，不再有AB布局、观察专用或B冻结重放模式。`--credits-config`可指定私有本地网关配置，在试验前后各查一次账户余额；每轮 `usage.json` 和 `.runtime/accounting/` 记录调用次数、请求体积、时间及可用额度变化。账户余额差额不是隔离的单次请求定价。

检查：`PYTHONPATH=src OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 <python> -m pytest -q`。普通数值控制与静态抓取/放置预览仍是独立诊断，不由整任务入口调用模型执行。

持物参考在一次实际抓持中保持原点集和reference_id。深度矛盾后保留suspended证据，不在刷新时改用近手连通块；仅依赖held_center/held_bottom的未派发动作不可绑定，当前像素/pad/EEF恢复仍可用。A unchanged还需新深度支持原点集；相对姿态changed保持旧点为历史，不自动改附着。当前bind以point_set_scope区分单刚体子集和混合/未知；后者仍可选单点，不能整组传播为持物形状。当前局部绑定不覆盖历史完整注册模板。T1保留原编译ID、分段attempts和整段tracking；正常搬运只退役世界像素，不因此反复触发注册。


若同一物体仍在爪内而相对手姿态已变，可在当前片段的 `refresh_object(mode=bind)` 中设置 `rebind_held_pose=true`，并如实填写 `point_set_scope`。程序先暂停旧相对手参考，再尝试以当前干净片段重定位这次抓持原有的同一批点；匹配唯一且受当前RGB-D支持时更新位姿，原点/ID/颜色保持。匹配不足、混合或歧义时继续暂停，当前片段仍可选点。该操作不新建抓持、不清接触警告，也不使旧世界像素重新有效。普通bind不增加匹配开销。首次原图像素和采样坐标在连续更新中保留，避免用变换后的世界位置误查原像素。


异步模式在同一条整任务命令上增加`--async-planning`，其余配置与纯IK执行器共用。同一个A在当前草图执行期间，通过`draft_next_sketch`准备紧接一个子任务的完整草图；只使用冻结历史、已有几何及最近真实反馈，不读实时机器人或新增现场工具。当前段正常结束后直接执行下一段，包括抓取、放置、开闭爪和活动结构，不另发A确认请求。preconditions仅是规划依据；没有视觉确认开关。

自动接续保留候选哈希/运行/批次/请求/物理步/一次消费、实际完成、接触和当前深度矛盾检查。语义未知、正常抓持epoch变化、缺少新的A评估不单独阻断；实际用到的点源/持物参考仍须当前有效，所有原真实IK/FK、预算和IK-only约束不变。程序派发独立记账，不制造A实际持物声明，不增加模型请求或A工具次数，不认证任务成功或无碰撞。

执行失败时立即退役旧候选并中断仍在生成的HTTP请求，清理连接和原工作线程后接同A恢复，不等待旧草图生成完毕。完整返回的旧候选保留为不可执行参考，不完整生成只保存已收到的原始流和取消记录；主动取消不当成断网重发或格式错误，API尝试与已知用量仍计数；同一A从真实停止状态画恢复段，恢复执行期间重新准备后续段。已完成动作不重放、失效坐标不复活、旧后缀不自动拼接。原先专门的候选审批工具、复核提示和调用方已删除。本轮取消传播使用独立18773端口网关（本地源码.runtime/flowith_probe/cancel_source_v9、二进制bin/flowith2api_v9_cancel）；试验后已停止，原18765/Mac服务保持运行。未来若需把取消传递至上游，应显式使用支持请求context取消的网关；客户端中断本身不认证上游停止计算或计费。

当前执行段预计完成整个任务时，提前阶段可用`status=finish_review`及reason提交终态提议；它不宣称未来成功，也不产生动作。段末同A获得实际反馈，使用正常7工具finish或继续恢复。非终态仍须完整草图，不允许defer，不强制编造wait。

请求串行，机器人和几何仍由原线程独占；网络暂停/授权重发回原线程，源历史、原图/点表、手图画法和反馈图保留。每段提前规划前沿用既有上下文整理策略，最新实图随反馈进入下一请求；不新增默认图片或模型轮次。提前请求/失败/恢复计入原预算，重叠和段后等待分开留档，不用重叠时长证明提速。当前Sol low/65536保持；协议72首轮Task0验证3次自动派发及同A失败恢复，段后等待29.206秒；同源追加轮同样3次自动接续，段后等待9.036秒、无T2。两轮均成功，样本不足以推算稳定成功率、长程收益或因果加速比。
